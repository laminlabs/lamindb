# Issue 1248: preserve nullable schema fields in record feature dictionaries

## Outcome and agreed behavior

Issue: <https://github.com/pfizer-collab/laminlabs/issues/1248>.

The original message supplied in chat reports that reconstructing a record from
its existing type and `features.get_values()` fails on blank nullable fields.
The original experiment was registered with LaminDB 2.11; construction under
2.12 reports missing required features. GitHub issue/comments access returned
404, so this investigation uses the supplied message rather than unseen comments.

The user clarified the desired behavior: keep required features required, and
have `get_values()` return missing nullable schema fields as `None`.

Implemented behavior:

- For saved records with a type schema, `features.get_values()` includes missing
  nullable members as `None`, including optional nullable members.
- Existing values and derived/index values are preserved. Missing non-nullable
  members are not synthesized. Records without type schemas, unsaved records,
  artifacts, and runs retain their previous getter behavior.
- Explicit `None` satisfies a nullable feature during record type assignment,
  for both feature-name and `Feature` keys. Omitting a required key still fails.
- Null schema index values remain invalid, even when the index feature is nullable.
- Nullable datetime values supplied as `None` receive a datetime-typed null column
  when converted for dictionary validation. DataFrame column-presence rules are
  unchanged.

The implementation and focused regression are locally verified. The shared
playground reproduction remains unverified and paused at the user's request.

## Contract and cause

[Schema.minimal_set](../lamindb/models/schema.py#L489) requires schema members by
default, with exceptions through `optionals`.
[Feature.nullable](../lamindb/models/feature.py#L1278) controls allowed values,
not whether a schema member may be omitted. Ordinary features default to
nullable, and existing record-assignment tests explicitly enforce required
nullable members. The [record guide](../docs/manage-records.md#L76) documents
this distinction.

The failure combines two behaviors:

1. [FeatureManager.get_values](../lamindb/models/_feature_manager.py#L1491)
   previously returned only stored/derived annotations. Record annotation
   persistence skips `None`, so a blank schema field disappeared from the result.
2. In [record type validation](../lamindb/models/record.py#L186),
   `_assign_name_keyed_values` and the `Feature`-key path used
   `_missing_feature_value` to discard explicit `None` before the required-member
   check. Therefore adding `None` to the dictionary alone did not suffice.
3. `DictCurator` then converts a dictionary into a DataFrame. A plain nullable
   datetime with `None` was inferred as object dtype and rejected despite its
   nullability. The timezone-aware datetime path already performed conversion.

Commit `a1ad7d07197e4eb485a4d790c7622addfc73a8f0` introduced record type-assignment
validation. Tag `2.11.0` does not have `validate_data_record_type_assignment` or
`_required_schema_features`. This explains the new validation boundary for old
records without changing the required-versus-nullable distinction.

## Implementation and impact

The plan was to fill nullable fields on reads and retain explicit `None` through
assignment, while keeping the required-member calculation intact. The datetime
conversion was an additional fix justified by a measured failing edge case.

- `_feature_manager.py`: fill missing nullable schema members using `setdefault`
  in the public getter, after stored and derived values have been read.
- `record.py`: retain explicit nullable `None` in both key paths; explicitly keep
  null index values in the missing-feature check. `_required_schema_features`
  and its optional-member rules are unchanged.
- `curators/core.py`: add a narrow all-null nullable datetime conversion for
  dictionary validation. This does not coerce non-null datetime strings or change
  DataFrame validation.
- `test_record_basics.py`: extend the assignment regression; add nine datatype
  round-trip cases; update existing assertions for nullable fields after null
  imports, annotation removal, and relation changes. The existing stored-type
  loading test now explicitly uses a non-nullable feature to retain its invalid
  record precondition.

No stored-data migration or null annotation writes are required. Record getter
results gain keys, so callers checking key absence must instead inspect `None`.
Reading a typed record's features adds a schema-members read. Dictionary-based
curators also benefit from the nullable datetime conversion. Actual empty
collections returned by derived relations are preserved rather than replaced.

import sys
from uuid import uuid4

import lamindb_setup as setup

setup.connect("allavinner/playground", _write_settings=False)

print(f"Invocation: {sys.executable} {__file__}")
print(f"Instance: {setup.settings.instance.slug}")
print(f"Runtime: LaminDB {ln.__version__}; Python {sys.version.split()[0]}")
print(f"Source: {ln.__file__}; Backend: {connection.vendor}")

prefix = f"issue1248_{uuid4().hex}"
created = []


def save(obj):
    obj.save()
    created.append(obj)
    return obj


try:
    feature = save(ln.Feature(name=f"{prefix}_note", dtype=str, nullable=True))
    schema = save(ln.Schema([feature]))
    frame = save(ln.Record(name=f"{prefix}_type", is_type=True, schema=schema))
    legacy = save(ln.Record(name=f"{prefix}_legacy"))
    # Model an existing 2.11 row without invoking the new assignment validator.
    ln.Record.objects.filter(pk=legacy.pk).update(type_id=frame.pk)
    legacy = ln.Record.get(legacy.uid)

    print(f"Command: ln.Record.get({legacy.uid!r}).features.get_values()")
    expected = {feature.name: None}
    actual = legacy.features.get_values()
    print(f"Expected: {expected!r}")
    print(f"Actual: {actual!r}")

    print(
        f"Command: ln.Record(name={prefix + '_copy'!r}, "
        "type=legacy.type, features=legacy.features.get_values())"
    )
    copy_ok = True
    try:
        ln.Record(
            name=f"{prefix}_copy",
            type=legacy.type,
            features=actual,
        )
        print("Expected: constructor succeeds; Actual: constructor succeeded")
    except ln.errors.ValidationError as error:
        copy_ok = False
        print("Expected: constructor succeeds")
        print(f"Actual: {type(error).__name__}: {error}")

    print("Note: required key remains present with None; copy is never saved.")
    passed = actual == expected and copy_ok
    print(f"Result: {'PASS' if passed else 'FAIL'}")
    assert passed, "Nullable schema field was lost or explicit None was rejected"
finally:
    for obj in reversed(created):
        obj.delete(permanent=True)
    print(f"Cleanup: deleted {len(created)} objects created by this script")
